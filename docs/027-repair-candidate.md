# 0x27 维修候选试刷单

日期：2026-11-02。适用：nRF52811、S112 7.3.0、UC8179 7.5 寸三色（BWR）、800×480。**这是未完成实机验证的维修候选，不能视为已修复版本。**

## 改动与边界

本候选仅将 S112 广播标志由 Limited 改为 General，并将应用、OTA 与 legacy 打包版本同步为 `0x27`（39），用于隔离广播配置问题。未修改 SVCI，也未补充旧配置迁移；两项独立风险仍在。

保留 0x26 固件、日志与原始故障现场，**先取证，再试 0x27**。请按 [0x26 维修取证单](026-repair-handoff.md) 备份现场并记录实际 bootloader/settings 布局。

## 交付内容

应用大小 **52,984 字节**，地址范围 `[0x19000,0x25ef8)`。

- OTA：`EPD-nRF52-7.5-ota.zip`；SHA256 `bf698d8ef302cc84ae0a3c57df015cd74d90008997b192d21029d86c573d06d4`。
- BIN：`EPD-nRF52.bin`；SHA256 `31405a0aafa098cfdde4d6b088b051f7d60d82f8e7755b8f470d2575ad6c993a`。
- 与故障0x26 BIN相比仅两字节改变：地址 `0x19b88` 的标志 `05→06`、`0x1a6ce` 的版本 `26→27`；其余应用字节一致。
- 其它文件见 `SHA256SUMS.txt`。维修套件外层ZIP不是OTA，请选择其中上述OTA文件。

`EPD-nRF52.hex` 和 BIN **仅包含应用**，不含 SoftDevice、bootloader 或 bootloader settings，**不是完整恢复 HEX**。ELF、map用于调试；`source-change.patch`保留最小源码变化；`BUILD-INFO.txt`说明构建来源。

优先通过原 bootloader 的 DFU 更新，让原 bootloader 自行维护 settings。当前无广播入口时，技术人员需先用有线调试确认可用的 bootloader 入口。若必须 SWD 直接烧应用，由技术人员核实实机布局并生成与实际 bootloader 匹配的 settings；只改应用而保留旧校验信息可能导致 bootloader 拒绝启动应用。不要直接全片擦除；本套件不提供未经核实的完整 HEX 或固定 settings 模板。

## 试刷与验收

1. 保存现场，核对硬件及文件校验，记录 DFU 或 SWD 路径，保留刷写工具输出。
2. 分别验证日历、时钟、相册：每种模式设置后重启，记录广播、连接和屏幕状态。相册约60秒周期、约2秒广播窗口，扫描至少覆盖一个完整周期；日历/时钟检查连续广播。
3. 每种模式通过 GATT 读取应用版本，确认 `0x27`（39）；选包版本和“传输完成”不能代替读回。
4. 每种模式断电冷启动，再扫描、连接并读回版本，记录配置是否保留。
5. 失败时保存 R0、PC、LR、SP、复位/故障寄存器和调用栈，用本包 ELF/map 定位。旧0x26证据中的固定地址只可用于确认匹配旧图像后的取证。

离线验证：GCC 14.2.1 构建、nrfutil 6.1.7 打包、init版本/大小/哈希、HEX/BIN/ELF一致性、ECDSA签名和两字节差异核对通过。新包与此前0x26使用同一签名公钥，仓库参考公钥验证也通过；实机 bootloader/settings 尚未读取。

解压全部文件后可执行 `python verify_candidate.py` 复核结构、哈希、版本、地址与文件清单；脚本只用Python标准库，不连接或刷写设备。三模式启动、广播、GATT读回和冷启动重连均待实机完成。
